# 透明的实打距离

本文件是技能与APP的产品规范。现已提供 [v0.1.1风温湿度混合模型](weather-algorithm.md) 和可运行脚本；它以carry结合工程先验区间计算，未完成实场标定，不是已验证上线的弹道引擎。不从用户描述的图片推断实际输入；示例数值只展示格式，不能拿来当模型系数。

## 先定义“按多少准备”

原始距离是当前位置到明确目标的测量值，注明水平/斜距、来源与目标类型。实打距离是基于明确基准环境、特定球员及候选球杆/弹道，将当前条件下的需求转换为基准条件下的等效距离范围，不是把测量值改写，也不是保证实际飞行距离。

carry（空中落地）与含滚动的起终点总距分别建模。攻果岭、强制飞越和开球落区的目标不一样，必须说明估算针对哪一个；把旗位等效距离算出来不代表过水或后方容错已经满足。不同候选球杆/弹道可能有不同修正，不能给全球包通用单一实打数。基准若已用当天环境校准，避免再重复调整天气。

## 启用条件与当前缺项

先检查规则模式、APP实际输入、模型适用性、个人样本与数据质量。当前没有球道海拔和果岭坡度；海拔及高差项显示不可用，不用0表示平地。球员说上坡/下坡可以作为现场自报参与条件讨论，不等于可靠高差测量或已知补偿码数。果岭坡面属于推杆读线，不能拿来直接修正全挥杆。

风、温度、湿度等只有带来源、观测时间、单位、地点/高度与质量的输入才可作为计算证据。天气站/预报与球位实测区分，阵风与持续风、风向“从哪里来”与相对目标线方向区分。没有有效风速时不把“微风/两格风”强转固定码数；只知道温湿度也不表示已掌握全部空气密度条件。缺失或过期字段标明不可用/未计入，不默认无风或平坦而隐藏。v0.1.1混合模型对缺当地气压有明确例外：使用标准气压101325Pa、标为估算并降级，不当作实测或未知海拔已解决。

区分有标记的工程先验估算与经验证的个人建议：v0.1.1可在适用域内给低可信估算范围，仍标未实场验证；要发布可靠选杆功能，需经验证且适配输入与球员的模型或个人校准。没有模型时只讲趋势、未知与需核验条件，不凭文字感觉输出181—184之类区间。温湿度并非天然“固定小幅”，不能套通用百分比或每度固定码数。数据丰富但未经校验时仍不开放精确功能。

## 可解释的计算账本

APP保存：原始距离及测量质量、目标/单位、基准环境、球员能力/候选杆与弹道版本、模型版本、每项原始输入/来源/时间/质量、是否应用、缺失原因、相互依赖、等效距离范围及其生成方法。置信表达依据定位、天气时效、个人样本、模型验证与缺项的实际影响，不能因“缺海拔”机械标中等，或未经校准给80%置信度。

两种解释方式分别处理：

- **加性近似**：统一单位、符号与基准，明确正号表示需按更远准备。最终值由原始值和所有有效修正项按同一口径得出；对已经联合处理的输入不能再逐项重复加。不能把各项范围端点简单相加冒充已校准的不确定性区间，需说明组合与相关性方法。
- **非线性模型**：用联合计算给最终范围；不能把风、温度等分别单算的差值伪装成可直接相加的原因。若展示分项归因，说明分解基准与方法（v0.1.1采用对称Shapley，旧弹道原型采用固定顺序），分配或列出交互/剩余项，使账本数值对得上；无法可靠分解就只给主要影响与联合模型结果，不编分项码数。

计算后检查单位、符号、目标、距离类型、重复调整、缺项和分项一致性。屏幕四舍五入导致的差值要明确标示或统一计算展示精度，不能留一组表面相加不等的数字而不解释。保存可复算输入与最终值；检查失败则停止该数值输出，退回原始距离和定性说明，不让语言模型自行凑数补齐。

## 风与横向目标分开

风可影响纵向需求与侧向落区。两者独立输出与验证，不能把“顶风加几码”当完整风处理。横向瞄点还依赖个人散布、弹道、真实落区与障碍；没有适配模型和几何数据，不报精确偏移量，不一律向风吹来的方向瞄若干码。实打距离的计算不能自行决定瞄点或替用户选择球路。

## 语音与屏幕

用户只问“还有多少”时仍先报明确测量对象的原始距离，按问距记录约定补问上一实际杆号；不擅自输出实打选杆或拉长策略讨论。用户问“实际按多少打”、进入策略交流且规则允许时，再给有依据的范围与一两个主要因素。用户追问原因或杆号依据时解释可审计的输入、模型依据与取舍，不编造公式或内部计算过程。

屏幕在功能实际实现时可显示：

| 项目 | 内容 |
|---|---|
| 测量 | 目标、原始值、水平/斜距、来源、观测时间与质量 |
| 实打估算 | 候选杆/弹道、基准、范围、适用目标与是否含滚动 |
| 有效因素 | 输入值、来源/时间、质量、影响方向及可解释的归因 |
| 未计入 | 当前高差不可用等缺项及可能影响，不能显示0码 |
| 可信程度 | 依据和限制，范围生成方式；不是无依据的概率 |
| 计算核对 | 加性账本或联合模型说明、交互项/舍入说明、模型版本 |

格式示例（仅在对应数据与模型确有依据时）：“到旗杆水平177码。按你这支杆的已校准数据，顶风和低温下可先按181—184码准备；高差还没计入。”若坡向是关键缺口可再问一个现场观察问题；如果未知高差足以改变结论，应暂缓最终选杆，不能把不完整区间说成全部条件下的最终答案。不存在模型时，改说“177码是水平距离，顶风可能增加需求；现在缺少可靠修正依据，先核实现场条件”。

## 分阶段交付与回归

先验证原始距离/来源展示和缺失标记；再用真实数据校验风温湿度与个人弹道的范围模型；以后高差与海拔各自完成坐标/基准/精度与实地验证后接入。不能因为少一两项就把其余因素称为已上线。当前不开发APP代码时只交付规范，不声称屏幕或引擎已实现。

验证覆盖：无风/逆顺横风、阵风、数据过期、候选球杆变化、当日校准重复修正、米码混用、强制飞越前后风险、高差缺失、联合交互与舍入误差。对照真实结果时区分模型误差与执行偏差，使用独立案例而非仅挑成功球；正式比赛功能检查独立且优先，不能因输出改称“体感范围”就绕过限制。
