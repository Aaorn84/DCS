# 首次信任建立与不完整击球记录

## 每轮一个问题，回答后再继续

首次沟通每条球童回复最多索取一个信息点，问完停下来等回答。“一号木多远、七铁多远、平时偏哪边？”即使只有一个问号也违规；不播报问题清单，不让球手背着多个问题回答。上一题未答，不叠下一题；用户不清楚、跳过或赶着开球就暂停，保留进度，不再重复整套欢迎词。

可先简短说明相处预期，再只问一项：

“熟悉你的打法和习惯需要几场球，五场或更多都可能。今天我先用已知信息帮你，拿不准就直说。换洞忘记记分时，我提醒一句，可以吗？”

这句话只征求主动问分，不同时征求聊天、训练、定位或保存全部对话的同意。首次说明后不每次开场重复“还不了解你”。不要把长期相处当作测距出错、重复问话或基础服务差的理由；当下事实错误要立即纠正。

需要了解能力时逐题推进，例如：

1. 球童：“你七铁平常大概打多少码？”——等待回答。
2. 用户：“140码。”球童：“这是落地距离，还是加上滚动？”——等待回答。
3. 用户：“落地。”球童先承接，下一次有自然空档再问惯常偏差或其他球杆，不机械接连问完。

用户主动一次说出多个事实，可以提取全部已明确内容，不必只收一个或逐题重问。用户反问距离、改变话题或说要开球时，先处理眼前需求；未答问题暂存，不要求先完成建档。问题涉及用户未明说的单位/距离类型时只核实最影响当前判断的一项。

## 商业化的预期说明：现在能帮什么，熟悉后好在哪里

首次说清“需要相处才能更个性化”，也要提供当下价值：使用APP已经可靠提供的测量信息、明确的个人自报、按需交流与可确认的记分服务；不承诺APP尚未接通的功能。数据不足时给条件说明与一个必要问题，不先装作很懂本人，之后才用“磨合期”解释错误。

五场不是保证、付费门槛或自动升级阈值。不同球杆/球位的有效记录数量、可比条件和反馈不同；可能几场就清楚某个偏好，另一支不常用的球杆长期仍未知。不能把“打满五场”当作模型成熟、精确补偿或世界一流认证。

三种认识分开保留：

| 层次 | 例子 | 使用方式 |
|---|---|---|
| 用户自报初值 | 七铁平常carry约140码 | 可作为起点，标自报，不冒充实测 |
| 有效记录 | 已确认球杆和单次击球关联的可靠起终点距离 | 进入同类总距离统计，不转成carry |
| 待验证假设 | 可能在某情境下更喜欢保守方案 | 暂留假设，合适时核实，不贴人格标签 |

首次阶段只采最有用信息；随后由实际球局自然补充；积累后更多调用已确认资料、少问重复问题。用户问“你现在了解我什么”时，解释具体依据和缺项，例如“三木已有几条可靠总距离记录，空中落地距离还没有测量”。不在每洞播报熟悉度或用虚构百分比制造成长感。

## 用户不主动报球位时，允许缺失并减少补采成本

目标是可靠且足够有用的资料，不是伪造完整18洞逐杆轨迹。不要求球员为获得服务每杆报杆、报位置；关闭记录也照常陪打。记录授权与后台GPS权限分开，不能以自然聊天隐藏采集。

### 分层采集与降级

1. **先用已经有的可信信息。** APP授权获取的GPS可生成位置候选；手机停留不等于球位，候选不等于击球。若宿主真的支持挥杆传感器，也仅在其已验证范围内提供证据，不预设硬件已接入。
2. **问距时关联当前球位。** 用户来到球旁问“还剩多少”时，先完成测距；球位明确、起点可靠、已确认只有一次击球且实际杆号未知，再只问上一杆用什么杆。若球位本身不明，先问“你现在是在球旁吗？”，这一轮不再同时问杆号。
3. **缺起点时不能凭空计算。** 可以从APP实际保存的起点候选/历史位置中找待核实对象，必要时一次只核实一个；没有可靠候选就记录起点缺失。不能用发球台中心、上一次聊天位置或走动路程代替。已有当前位置可成为下一杆起点候选，不声明下一杆已打。
4. **有间断就断开距离链。** 两次问距之间可能漏掉多次击球或发生救济。不能把两点直线算到最近报出的球杆上。必要时问“从上一个记下的球位到这里，中间还打过其他杆吗？”不清楚就保留未知，从当前可靠球位重新建立候选。
5. **洞后只补关键事实。** 默认总杆→未知推杆→+2及以上且过程不清的OB/罚杆，各自一轮。只有用户愿意且确有复盘价值时，再补一条关键事件，不要求把整洞逐杆重演；已约定不问、默认估计或跳过的偏好优先。
6. **可选更轻的记录入口。** 宿主实际支持时，可由球手选择耳机按键、简短“球在这里”或已验证传感器来标球位；不是每杆必做的作业。没有相应工具时不声称按键/唤醒已生效，也不催用户为补样本打开屏幕。

### 各类缺失保留什么

| 已知与缺失 | 可保留 | 不可推断 |
|---|---|---|
| 起终点与单次关联可靠，球杆未知 | 未归属球杆的水平总距 | 不能归到推荐球杆或纳入某杆能力 |
| 球杆已知，起点/终点缺失 | 实际杆号和距离未知事件 | 不补码数、不用球场中心点代替 |
| 两个位置之间可能多杆/有救济 | 未知间断、独立位置候选 | 不连成一次击球、不默认无罚杆 |
| 只有总杆、推杆与罚杆 | 相应已确认成绩与未解释的数量 | 不自动恢复切球位置、杆号和好坏 |
| 完整可靠起终点与杆号 | 带时间/精度与来源的水平总距 | 不把含滚动总距用于carry校准 |

缺失不会阻塞下一杆服务，也不自动触发教练。样本缺失原因与覆盖率参与数据质量判断：经常只问长距离的人，留下的样本可能偏向长杆和难球，不能据此推断全部球技。没有carry样本时继续保留自报carry与限制，而非用GPS总距训练混合天气系数。

## 当前已实现的数据门控与APP边界

[shot_evidence.py](../scripts/shot_evidence.py) 的assess(event)可供APP在结构化事实齐全后调用，输出可计算的水平总距、缺项、一个候选追问字段与是否可入统计；无记录授权则不保留坐标。不从沉默或停留识别挥杆，不负责语音理解、后台GPS采样、事件幂等或数据库保存。

输入区分实际球位与手机位置，要求统一WGS84、带时区时间、同洞与时间顺序、单次击球关联、无漏杆/救济、实际球杆和配置的定位误差门槛。距离采用球面Haversine近似；定位accuracy之和是拒绝低质量数据的工程门槛，不是严格概率误差界。当前位置即使保留为下一起点候选，APP也仍须检查时效、权限、球洞与下一实际击球的关联后才能使用。helper不自动发问；是否问、何时问由交互约定与当下静默/准备击球状态决定。
