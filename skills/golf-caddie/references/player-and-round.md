# 数据与复盘

## 最小可用档案

首次每次只问一个字段并等待回答；按任务逐步收集，未知字段保持null，不用差点推算个人距离。

| 实体 | 重要字段 |
|---|---|
| 球员 | 单位、左右手、差点及日期、实际能力与可靠球路、大失误方向、已练熟/未练熟的击球、交流/失误后回应偏好 |
| 当天状态 | 本轮目的、当前信心与顾虑、紧张/疲劳的用户自报及时间、希望获得的支持；默认会话内使用，不写成永久心理标签 |
| 伙伴记忆 | 用户认可的称呼与相处方式、兴趣喜好、重要经历的必要摘要、希望/不希望提及的话题、来源与日期、授权范围、更新/删除状态 |
| 球杆能力 | 杆名、落地与总距分别记录、短长分布、左右偏移、样本量、球型、球位、环境、日期与来源 |
| 球局 | 球场、发球台、日期、赛制、正式规则状态、当地规则核验情况、已确认成绩 |
| 当前杆 | 洞号、杆序若已知、球位、距离及测量对象、风/坡的来源与时间、真实危险区、目标与方案 |
| 击球距离事件 | 起终点候选与确认状态、实际杆号/未知、水平起终点距离与精度、含滚动/非落地、来源、问距关联与去重标识；默认静默记录、按需播报，不等于正式计分 |
| 决策事件 | 当时已知事实、未知项、球手本杆意图/顾虑、讨论候选与理由、球手接受或修改的方案、最终执行建议、实际结果及其来源 |
| 服务偏好 | 轻松陪伴/按需策略/训练跟进等独立偏好，适用本场或长期；与说话风格及成绩目标分开，用户可修改 |
| 交互约定 | 主动问分/细节/特殊障碍事实提醒/策略邀请/闲聊分别设置、临时与长期范围、静默与事件去重/取消状态、版本；与教练偏好独立 |
| 教练偏好 | 未选择/开启/关闭、本场暂停范围、一次性建议与持续跟进的区分、邀请/回复范围、版本；关闭不自动删除历史 |
| 教练计划 | 一个已接受的主要重点、基线与证据、主要练习、观察口径、逐场执行/结果、巩固标准、状态与版本；详见跨场教练流程 |
| 记分草稿 | 洞号、总杆含罚杆、推杆/罚杆可未知、确认状态、版本 |

当前上下文先读取用户已提供资料，不要求重复录入。不自动提取私密录音；长期写入前确认内容。无数据库时可以经授权写本地结构化文件；向用户区分本次会话、待保存草稿与已持久化资料。确认写入成功才说“已保存”。

换洞主动关照及晚报洞号绑定，见 [交互约定](interaction-agreement.md)。当前洞与上一洞待确认成绩分开保存，用户正在2洞时补报1洞不改写2洞。GPS不自动生成正式成绩。

## 跨场统计与GPS来源

GPS与逐场学习遵循 [接入契约及更新流程](gps-and-learning.md)。事件补充定位时间/精度、地图与坐标版本、起终点确认、距离类型、用户/球局/事件标识、授权范围及上下文版本；每个衍生统计记录来源事件与适用条件。当前没有海拔和果岭坡度，显式缺失不补零。球员自报、测量、统计与候选推断分别存储；纠正事件后重算相关统计，不能只改展示文字。

## 每洞成绩核对：总杆、推杆、必要的罚杆事实

用户声明洞结束，或可靠换洞候选依交互约定允许提问时，先取得本洞总杆；已有总杆不重复问。除非用户已明确约定不追问或使用标注的默认估计，否则推杆数未知则接着中性问“一共几推？”，不限定“两推还是三推”。用户已说“六杆，两推”就不再问推杆。可以零推，不从GPS进入果岭推断几推；球员不记得或不愿答可跳过，未知不补零，不能因缺分项拒绝保存已确认总杆。

报“加一、+2、保Par”等相对成绩时，按实际洞号和可靠标准杆换算；标准杆未知先核实，不假定四杆洞。总杆默认含罚杆，表意含混时核实，绝不在已含罚杆总杆上再加一次。

本洞相对标准杆达到+2及以上，且现有记录不足以解释过程或罚杆情况时，推杆后再问一个关键问题：“这洞有OB、下水或其他罚杆吗？”已有相关信息不重复问；若只知道发生过OB但罚杆数量不明，追问实际处罚或关键球的处理，而不是再次问有无OB。+2不证明有罚杆；用户明确没有就不继续引导他说有。低于+2但存在明确事件疑问时也可以针对性核实，不能据低杆数断定零罚杆。

用户报有罚杆但数目/类型不明，按必要性分步核实：发生了什么、涉及哪支实际球杆（若需要且未知）、罚杆总数是否已计入总杆。OB次数、遗失球次数、罚杆区事件与实际罚杆数分开记录；“开球OB，暂定球也丢了”不能草率写成OB一次或一个罚杆，也不自动给两球都贴OB。涉及规则处理不确定时查询官方条款，不把成绩核对变成强迫重演所有挥杆。

补齐当前愿意提供的信息后，一次复述总杆、已知推杆和已核实的罚杆事实，请用户确认；确认并写入成功才说已记录。例如实际五杆洞报“加二”→“这一洞几推？”→“两推”→“这洞有OB、下水或其他罚杆吗？”→“没有”→“本洞七杆、两推、无罚杆，确认吗？”任何数字都来自该洞事实，不套用例子。

状态：总杆草稿 → 补问未知推杆 → 按条件核实OB/罚杆 → 复述确认 → 写入成功。用户已确认总杆但想跳过分项时，保存已确认部分，分项保持未知；后续补充分项需确认更新版本。安静、准备击球或明确不答时立即收住，不以“必问”压过当前打球节奏；重复问分事件不重复问已经答过的字段。

用户要求默认两推等便利规则时，按 [默认值与服务改进](service-improvement.md) 分开确认值与估计值，停止对应追问；默认值不能参与精确账本重建或推杆训练评价。后续个性化反馈可改变询问频率，不改变数据事实的来源标记。

## 不完整事件账本，不用差额造挥杆

场上咨询不是完整挥杆检测。熟悉球场开球不问、长距离问距、近果岭目测都可能发生，不能用没说话证明没有打，也不能用移动证明已经打。能力档案中“50码”是用户自报的交流习惯范围，不是自动识别切球或预测杆序的阈值。

只有所有相关计数口径一致，且总杆、推杆和罚杆数均可靠时，才可计算“非推杆实际击球数 = 总杆 - 推杆 - 罚杆”，进一步对比已确认的非推杆事件数量。这只给出尚未解释的击球数量，不说明发生在哪里、用了什么杆或是否切球；一项未知就不能把差额当精确数量。

四杆洞五杆、两推、无罚杆，且确有两次非推杆击球已确认，则还有一次非推杆击球未解释；不能自动定为40码切球。四杆洞四杆、一推同样不能证明未知那杆是“神切”，还需事实支持距离、球位与留球质量。问过距离不自动证明这是第2杆，GPS发球台停留也不证明第1杆已打。

如确需解释关键缺口，可在合适空档中性问“还差一杆没对上，那一杆是怎么处理的？”用户的回答才进入确认记录；不为账本完美闭环连续盘问。细节不愿说就保留未知，教练关闭也不因这次记分核实而恢复。事件缺失率作为统计质量的一部分，不拿候选拼成的假完整记录训练画像。

确认绑定当前草稿与洞号，过期或重复确认不多写；纠正生成新版本，撤销说明对象。同步冲突另行处理，不阻断语音陪伴。

## 复盘方法

先按用户意愿选择交流深度。默认可聊感受、分享高光或提供请求的成绩回顾，不主动发问题清单或改善作业。请求看统计不等于接受训练。教练关闭时不运行下面的训练重点选择与追踪，用户明确请求的一次分析只回答该范围；教练开启或本次明确愿意改善时才按以下流程开展。

1. 汇总已确认洞数与总杆；未打完不外推18洞成绩。可得时附推杆、罚杆与可比历史，说明缺失率。
2. 用当时已有信息评估决策：目标是否适配散布，风险是否被识别，球员是否有可执行方案；不能事后用结果倒推“本该知道”。
3. 执行评价须有目标与实际落点/球路证据。好球落水可能源于策略问题，好决策也可能遇到罕见失误；信息不足就标未定。
4. 先评估进行中的教练计划，按 [跨场教练流程](coaching-cycle.md) 决定继续、巩固、改练法或换重点；没有计划时才结合本轮目的选一个主要改善点，与用户确定练习、指标和复查条件。其他问题只作候选，不同时安排全套训练。小样本提供假设，不宣布永久技术缺陷。

只有距离、球位、结果和合适基准齐全时才算分项杆数收益；仅总杆与推杆数不能推断铁杆、开球或短杆各损失几杆。比较历史须考虑发球台、球场难度、天气、赛制和样本，不能把不同条件下总杆变化全部归因于技能建议。


## 缺失记录与样本覆盖

缺球位、球杆或中间有漏杆时遵循 [缺失处理](onboarding-and-missing-data.md)；不能为形成完整画像虚构事件。保留缺失原因与已确认/未归属/待核实状态，只有通过 [数据门控](../scripts/shot_evidence.py) 或等效的APP验证才将有效总距用于相应球杆统计，carry仍需另有落地证据。
