# 滚动通道和白桩边界修复

共享核心 1.4.0，数据集 shared-core-4。手机和网页调用同一份实现。

- 滚动段按多边形边界、有限白桩边界及端部交点分段，检查各区间和接触点。窄水域不会因一号码采样间隔而漏检。
- Carry落点和预计停球点均核对OB；落地后滚入OB的路线不再推荐。
- 落区横向宽度取连续可用区域，遇到已标障碍、白桩边界或地图空隙即停止。
- 这些限制作用于地面滚动和落点。飞行中的瞄准线经过沙坑或水域，仍按Carry飞越余量评估，不直接淘汰。
- 地图与边界预处理按不可变球洞对象、模拟模式分开缓存，地图替换后重新计算。

## 验证

新增6项回归覆盖窄水域、OB停球点、有限OB区间、模式隔离、球道/果岭接缝、地图空隙、Polygon内环、障碍边缘接触，以及策略层的滚入拒绝。已有飞越沙坑测试继续通过。

macOS arm64、Node24；凤凰山所有四/五杆洞发球台，5次重复，冷/热各60样本：冷计算p50/p95从3.499/5.636ms变为3.344/6.071ms；热几何从0.957/2.257ms变为0.974/2.843ms；100次相同策略缓存p50/p95仍为0.004/0.006ms。

Python3.12+Node24、本机HTTP、临时SQLite、凤凰山第1洞30次紧凑查询：p50/p95从3.634/5.012ms变为3.744/5.725ms；首方案从9.627ms变为10.199ms。毫秒级新增核对成本保留，不以取消障碍检查换取速度。

上述数据不含手机渲染、真实GPS、ASR/TTS和端到端语音时间；尚未做原生设备验收。
