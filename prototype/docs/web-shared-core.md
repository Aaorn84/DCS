# 网页共用核心接入

入口仍为 `http://127.0.0.1:8791/`。保留原有聊天、地图、每洞成绩、用杆折叠和Carry表格；刷新页面后普通事件改发 `core_event`。

## 事件链路

- 首次问答和选择球场：应用服务，不创建实际击球。
- 开始球局：服务器固化地图、球杆和最近五场参考，创建共用模型。
- 选杆、旗位、落点、事故与记分：`webJourney.ts`转换指令，`roundEngine.ts`执行。
- 策略：`strategy.ts`和`geometry.ts`，与手机同源；缓存按球局、地图、revision与意图失效。
- 保存：原事件与模型投影在同一事务提交，读写均隔离认证账号；回放用固定包，不取后来更新的地图。
- 赛后分析、教练与下一场：应用服务读取已投影的成绩和逐杆，不重新用旧规则解释场中操作。

网页仍需联网。手机离线记录权未释放时网页不能抢写；释放后能接续同一模型，不做成绩迁移。

## 重点验收

1. 开始前提交地图位置：要求先开局；不生成击球。
2. 开局、发球台位置、询问策略、确认球杆：未击球前用杆表为空。
3. “仅更新选点位置”只移动；“记录模拟击球落点”才记杆；修正落点不新增一杆。
4. 声音登记击球后提交落点只补齐原杆，询问落点时关闭识别。
5. OB回原位、红/黄桩救济和暂定球都通过共用规则，不能由位置自动确认罚杆。暂定球位置更新后可说“已到暂定球位置”；逐项确认救济条件后可说“确认在当前位置”。
6. 切洞不补成绩，不增加击球。补上一洞成绩不会写到新洞；已知上果岭杆数时可推算推杆并等待确认，未知时保留待补。
7. 失联重试不重复记杆，同event_id改内容拒绝；事故未处理时不能切洞。
8. 球杆范围、保底杆和用途显示来自核心最新档案。旗位不会写入实际用杆。
9. 完场可进入原有分析总结；更正成绩不能混在分析请求中绕过核心。
10. “核对事件重放”与已保存状态应完全一致。

自动化覆盖上述链路、手机接续、历史参考和不可变地图大小保护。实际麦克风识别准确率与语音端到端时延仍需真机测量。
