# 统一规则与分层策略

2026-11-23，共用核心1.7.0。手机和后台执行相同模块，地图不包含可执行规则或策略代码。

| 层级 | 模块 | 输入和职责 |
| --- | --- | --- |
| 统一规则和状态 | roundEngine.ts | 类型化指令、击球/罚杆/救济/成绩校验；偏好和地图不能改写规则 |
| 系统策略框架 | strategyPolicy.ts | 统一风险评分、推进比较、默认距离优先及个人偏好可调整的边界；不读取地图 |
| 个人策略档案 | personalStrategy.ts | 明确偏好、保底杆、有效路线选择观察、已有散布摘要；不依赖球场编号 |
| 球场分析 | courseAnalysis.ts、geometry.ts | 当前地图、球位、障碍、落区和相同球洞近期失误；不推断用户性格 |
| 方案编排 | strategy.ts | 按前述层级生成本次具体建议，保留当前球位/触球/旗位等补问 |

系统默认仍重视有效推进：无已检查到的罚杆暴露和重复失误时，优先比较一号木；普通长草不等同界外或罚杆区。个人控制倾向只对风险相当的候选增加保底杆与稳定球杆偏好，不把短杆或保底杆视为安全保证。目标落点和地面滚动通道仍必须通过核对。飞行线穿过障碍不直接淘汰。

个人偏好不是候选硬白名单。统一规则、可达性与现场风险优先于个人习惯；本次明确要求保守、分杆或进取，优先于长期偏好。单纯改选一支杆、不执行击球，不训练偏好。

## 个人档案如何逐步形成

- 可明确说“以后优先保守打法”“以后优先距离打法”“恢复系统默认”。场中和本机赛前均支持，不新增必答问卷。明确设置的优先级高于推断；临时“有没有保守方案”不改长期设置。
- 主动请求保守/分杆或进取方案、按该建议选杆且实际登记击球后，才产生一条路线偏好观察。默认推荐后的执行不计，避免系统用自己的推荐强化自己。其他方案请求不直接推断为保守偏好。
- 每场每洞最多一条，撤销击球同时撤销观察；最多保留60条。跨至少3场、累计至少8条有效观察、某方向占比至少70%时，形成可覆盖的控制/距离倾向。阈值是初始产品策略，不是统计学置信概率，也不把一次OB解释为性格。
- 已有散布摘要10样本起提供发展中证据，30样本起可提供稳定性参考；不扫描全部逐杆来计算偏好，不把含滚动落点校准为Carry。固定侧向阈值仅用于候选排序参考，不保证安全。
- 跨场使用遵守记忆授权。本机结束后将小型偏好档案带入下一场，未联网也可继续积累；后台从账号最新已结束球局读取个人档案，球场逐洞历史仍单独限制为同球场/Tee/地图匹配的最近五场。关闭记忆后新球局不继承历史选择观察。
