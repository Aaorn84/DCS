# 球局和个人档案一致性修复

2026-11-23，默认核心1.6.0，数据库schema3；保留1.4.0和1.5.0冻结核心继续原球局。

## 未结束球局不能提前释放

独立手机球局的“同步并结束离线记分”仅在本人确认结束后可用，手机release方法也先校验；后台在原记录权事务和账号锁内再次检查finished。进行中仍可普通同步，不影响本机记分。既有网页球局交接协议保留自己的释放语义，不将手机结束条件套到网页交接。

旧版误释放的未结束球局可明确“恢复记录权”：相同账号、设备、租约和精确cursor，无待处理事故/成绩且后台版本一致才恢复；重试幂等，不自动抢占其他设备。手机只在打开这类异常球局时展示恢复按钮。已结束球局不能借恢复入口重新写入。

## Carry及个人设置跨场继承

仅在跨场记忆授权下，将已结束球局中确认的Carry范围、保底杆、球杆用途、球道长杆资料状态和策略偏好带入下一场。暂估杆距不升级为自报Carry，沙坑用途不凭空变成全挥Carry。七号铁明确修改后同步更新估距基准，避免显示新7铁却仍按旧7铁暂估其他铁杆。

个人字段带原始修改时间、来源球局和事件顺序。仅实际修改设置或执行带路线选择的击球才更新对应字段版本；下一场读取、预览和继承不生成更晚的修改。撤销恢复值和版本。新核心增加这些元数据，因此使用1.6.0语义；1.4/1.5固定状态不改写。

## 旧球局晚上传不回退新资料

后台按账号保存已结束且授权球局的小型字段贡献，用原始修改时间和事件顺序合并，各字段独立，不用上传完成时间决定整个档案。原始开始时间用于选择最近五场策略参考，补传旧场不挤掉更近场次；最近五场限制不影响全部可比成绩的汇总。

字段贡献与原事件及同步cursor同事务提交；撤销结束使该场贡献撤回，重复同步不重复贡献。赛后关闭跨场记忆会移除该场贡献及后续复用资格。字段仅在完成/撤销时整理，普通询问不扫描历史或新增字段查询。按账号和字段建立索引，写入批处理。

## 核心升级不改变成绩可比口径

每场索引保留不含核心版本的记分口径摘要：18洞洞号、标准杆和公布长度，按同球场、同Tee且完整18洞比较。地图包摘要仍用于固定包真实性校验，不再作为成绩可比条件。公布长度130与130.0视为一致；不同Tee、长度/标准杆改变或成绩不完整仍不比较。

schema升级显式执行：根据原固定包补齐原始开始时间和记分口径，并为已完成且授权的旧球局补齐字段索引；每批最多100场，不改动原始球局、击球、成绩和命令。运行时请求不自动迁移。

## 验证与性能

完整回归覆盖上述四项，以及原1.4/1.5的断网前九洞检查点继续完成18洞、OB处理中断、首次注册回执丢失、重复同步、账号隔离、字段撤销和schema回填不修改原记录。
