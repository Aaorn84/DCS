# 升级后继续原球局

当前默认核心1.7.0，随App和后台一起提供1.4.0、1.5.0、1.6.0、1.7.0四个版本。旧球局读取固定包的core_version，不迁移状态、不改写版本、不删除原记录。新建球局仍使用当前核心。

## 执行路径

- `shared/core/runtime.ts`是静态版本白名单。旧规则、对话、几何、策略与开局资料组装保存在`shared/core/releases/1.4.0/`、`shared/core/releases/1.5.0/`和`shared/core/releases/1.6.0/`，内部依赖完全留在该目录。没有运行时下载或执行远程脚本。
- 手机冷恢复先验证固定包摘要、受支持版本和事件序号，再用对应核心重放收据。后续选杆、击球、罚杆、救济、记分、策略和摘要都使用同版本；不知道的版本保留数据并停止，不退回当前核心猜算。
- 未完成的旧开局准备也按原地图包版本组装，核对原始摘要后继续，不生成另一个球局ID。已下载旧地图保留给原球局，新开局需更新为当前版本资料。
- 注册前一直断网的旧球局，联网后仍用原始core_version和原始下载资料注册；后台以保存的资产、账号私有参考和对应核心复算摘要。已注册旧球局同样沿用原租约，不换ID或清空未同步队列。
- 后台共用工作进程内按固定版本选择模块，缓存仍受原有账号/球局/摘要作用域和容量限制。缓存包版本与状态版本不一致时拒绝；旧错误仍按规则错误返回，不当作后台故障或改由新核心处理。
- 网页事件、旧事件重放以及手机释放后的网页交接使用球局固定版本。健康检查中`sharedCoreVersion`表示新球局默认版本，`supportedCoreVersions`列出可续打版本；具体球局视图返回它实际使用的版本。

已覆盖1.4/1.5/1.6→1.7升级路径。更早已退役的旧网页实现、旧存储格式及未知核心不在支持范围；不会为兼容恢复那些旧业务分支。真实手机App升级、系统杀进程、GPS和麦克风仍需设备验收。

## 以后发布新核心

1. 修改核心语义之前，运行`python -B prototype/scripts/freeze_core_release.py`冻结当前核心的本地依赖闭包。脚本拒绝覆盖已有版本。
2. 在runtime.ts增加该冻结版本的静态入口，保留已经支持的版本；同步Python白名单。再提升默认核心版本并开发新语义。
3. 发布前执行`freeze_core_release.py --verify`及版本续局回归；CI检查冻结源码摘要和依赖闭包。手机与后台同时保留对应运行器，不单方面停止某版本同步。
4. 某版本是否可退役需先核对仍有未完成或未同步球局的影响，不能按固定天数自动删除数据或强制迁移。本次没有设置自动退役期限。

这保留的是可复现的历史发布内核，不是另写一套业务规则。修复当前核心时不得覆盖旧版源码；需要改变规则行为应发布新版本并单独评估旧球局处理。

## 验证

完整回归：业务142项通过；API106项中105通过、真实Redis1项跳过；客户端124项通过，合计371项通过。覆盖旧前九洞检查点断网恢复、旧开局准备恢复、未知版本不写入/不删除、冻结源码校验、跨版本缓存隔离、旧网页恢复、未同步/已部分同步两种18洞续打、OB处理中断、重复同步和释放。真实HTTP/PostgreSQL验证升级后73杆、1罚杆与本机一致，无重复事件。

同一darwin arm64、Python3.12/Node24、localhost HTTP与隔离PostgreSQL，凤凰山第1洞30次紧凑策略请求：改造前p50/p95 4.291/6.963ms、首次11.006ms；本次4.435/7.497ms、首次10.802ms。p95小幅波动，未见明显退化；不是手机、ASR、TTS或语音端到端指标。旧版源码约108KiB磁盘占用，不在每次请求复制；工作进程和缓存容量未随版本数增大。
